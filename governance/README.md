# 統治ルールの境界

統治の政治的な値と手続は、現行憲法の末尾にある一つの
`governance-rules` JSONブロックを正本とします。`policy.json`は初期値の検査用で、
憲法内の規則から同じ形へ投影されたものと一致しなければなりません。

コードが固定するのは、監査記録、入力schema、Discordの実在する権限と上限、
未知handlerの拒否、待機なし循環の拒否、調査手段の実装の有無など、実行を安全に
する技術的な境界です。
国会の開会間隔、1回で扱う議題数、継続審議の上限、公開記録からの議題発見の可否、
全員投票による早期開票、投票条件、AI席数、処分上限、承認数、上訴範囲、
席が使える調査手段とその手数、答弁やり直しの上限および状態遷移を変更するには、
完全な憲法改正案として国会の合議と投票を通します。
運営panelで変えられるのは、AI回数枠や既定の遡り日数のように統治の中身へ影響
しない運用値だけです。

## 席の調査

警察・裁判所・国会のいずれも、席は事前に詰め込まれたデータを読むのではなく、
**自分で読み取り専用のツールを叩いてから判断します**。使える手段と手数の上限は
実行規則の `investigation` にあり、コードは実装があるかどうかだけを検算します
（憲法第十五条3）。

- 席は**独立に調査し、独立に判断**します。事件化は「同じ記録を挙げた席の数」では
  なく「その構成要件は満たされていると判断した席の数」で数え、証拠は賛成した席が
  挙げた記録の和集合を採ります（憲法第六条4）
- 席が引用できるのは、その席が実際にツールで取得した記録だけです。取得していない
  IDを引用した席は結論ごと無効になります
- 取得した記録はあくまで索引で、証拠になる前に必ずDiscordから再取得してハッシュを
  照合します
- 裁判所が審理中に対象者へ不利な記録を見つけた場合、その場では認定に使わず、
  事件記録へ公開して**答弁期間をやり直します**。やり直しの回数は
  `investigation.maximumRedefense` を超えられず、上限後は既に示された証拠だけで
  判断します（憲法第六条6・第九条7）
- 調査で確かめた事実は席の**理由文**が語ります。ツールの箇条書きは既定では公開せず
  （`investigation.publicRecord` の既定は `none`）、完全な往復は
  `governance_investigation_steps` に残します（憲法第九条8）
- ツールループは毎リクエストで会話全体を再送するので、費用は手数の二乗で効きます。
  憲法は手数（`maximumSteps`）と1審議で受け取れる総量（`maximumOutputKilobytes`）の
  両方を固定し、上限に達したらその時点の記録だけで判断させます（第九条9）。
  憲法本文はDATAへ積まず、`read_constitution` で必要な条文だけ読ませます

## 国会

立法は、実行規則が定める間隔 (既定72時間) ごとに開く国会でまとめて行います。議題は次の2系統を同じ重みで扱います。

- 構成員が`議会`Forumに立てたスレ。スレそのものが提案で、国会が読むまでは
  討論の場です
- 公権力が直近の公開ログから見つけた反復する制度上の問題

議題ごとに、実行規則が定める独立したAI席が、討論・現行法・現行憲法を照らして
合議し、必要票を満たした結論だけを採ります。

- **立法**: 条文と執行定義を起草し、憲法適合を確認したうえで公開の記名投票へ進める
- **継続審議**: 投票にはかけないが、**その時点で書ける条文のたたき台は必ず出す**。
  聞きたい論点を添えて次の国会まで討論に付し、次回はその反応を読んで書き直す。
  前回の継続審議のあとスレに新しい発言が無ければ、もう一度は待てません（立法か不採択）
- **不採択**: 現行法で足りる、対象が個人、規則にできない要望などを理由付きで終える

継続審議で条文を出さずに質問だけ返す席は無効票として扱います。国会が何も決めない
まま人間に白紙を投げ返さないための決まりです。

議題スレの発言は、proposal行ができる前のものも含めて全部が国会へ渡ります。スレ自体が
提案だからです。また、公開ログに実例が見つからないこと自体は継続審議・不採択の理由に
なりません。憲法第七条1は**事前の**一般規則を要求しており、ログが短い・新しい・単に
静かなだけの可能性があるからです。

開会するたび、`手続`の`国会記録`スレへ議事録を1件残します。第何回か、扱った議題と
その結論、各議題スレへのリンク、次の開会予定が並ぶので、議題スレを個別に見なくても
「いつ開かれて何が決まったか」を追えます。議題が無かった回もそう書きます。

継続審議の回数は実行規則の上限までです。上限に達した議題では、席は継続審議を
選べず、立法か不採択のどちらかに収束します。結論が出たスレはアーカイブして
ロックし、一覧から外します。

事前の違憲審査という独立した段階はありません。憲法適合性は起草直後に同じ席数の
憲法パネルで確認し、満たせない草案は投票へ進めず継続審議へ落とします。成立後の
違憲審査は裁判所（`@裁判`）が担います。

討論、候補法令、利用者の入力はすべて未信頼データです。AIが候補にない対象ID、
未知の権限、未知のhandlerまたはschema外フィールドを返しても受理しません。
法律と憲法は起草時の対象hashを固定し、並行する別案が先に成立した場合は、
古い全文で上書きせず不成立にします。

## 法令集

成立した憲法と法律の公開正本はDiscordではなく、Cloudflare Worker + D1 にあります
（`worker/README.md`）。botは差分だけをoutbox経由で押し込み、失敗しても
idempotency keyで二重掲載になりません。接続先が未設定なら押し込みを行わず、
統治機能はDiscord内だけで動きます。

## 取締り

通報は`@通報`が受け、**警察**が実行規則の席数と必要票で即断します。裁判所は
**警察の処分が争われた事件**と、**警察が実行できない処分の事件**だけを審理します。

- 警察が単独で打てる処分と、必ず裁判所へ送る処分の区分は実行規則の
  `sanctions.police` にあり、重複できません
- 拘留は罰ではなく審理を確保する保全です。上限は `sanctions.detention.maximum`
  で固定し、不服申立ての期限を超えて続けられません。拘留中も本人は自分の事件記録で
  反論でき、拘留した時間は同じ事件の刑期から差し引きます
- 不服申立ては判決が出るまで取り下げられます。取り下げた時点で処分が確定します

開会間隔と同じく、これらの量的な値（警察の席数と必要票、不服申立ての期限、拘留の上限、
上訴の範囲）はすべて憲法の実行規則にあり、運営panelからは変更できません。
