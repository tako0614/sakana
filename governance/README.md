# 統治ルールの境界

統治の政治的な値と手続は、現行憲法の末尾にある一つの
`governance-rules` JSONブロックを正本とします。`policy.json`は初期値の検査用で、
憲法内の規則から同じ形へ投影されたものと一致しなければなりません。

コードが固定するのは、監査記録、入力schema、Discordの実在する権限と上限、
未知handlerの拒否、待機なし循環の拒否など、実行を安全にする技術的な境界です。
国会の開会間隔の上限、継続審議の上限、全員投票による早期開票、投票条件、
AI席数、処分上限、承認数、上訴範囲および状態遷移を変更するには、完全な
憲法改正案として国会の合議と投票を通します。

## 国会

立法は、定期的に開く国会でまとめて行います。議題は次の2系統を同じ重みで扱います。

- 構成員が`議会`Forumに立てたスレ。スレそのものが提案で、国会が読むまでは
  討論の場です
- 公権力が直近の公開ログから見つけた反復する制度上の問題

議題ごとに、実行規則が定める独立したAI席が、討論・現行法・現行憲法を照らして
合議し、必要票を満たした結論だけを採ります。

- **立法**: 条文と執行定義を起草し、憲法適合を確認したうえで公開の記名投票へ進める
- **継続審議**: 結論を出さず、聞きたい論点を公開して次の国会まで討論に付す
- **不採択**: 現行法で足りる、対象が個人、規則にできない要望などを理由付きで終える

継続審議の回数は実行規則の上限までです。上限に達した議題では、席は継続審議を
選べず、立法か不採択のどちらかに収束します。結論が出たスレはアーカイブして
ロックし、一覧から外します。

事前の違憲審査という独立した段階はありません。憲法適合性は起草直後に同じ席数の
憲法パネルで確認し、満たせない草案は投票へ進めず継続審議へ落とします。成立後の
違憲審査は裁判所（`@裁判`）が担います。

討論、候補法令、利用者の入力はすべて未信頼データです。AIが候補にない対象ID、
未知の権限、未知のhandlerまたはschema外フィールドを返しても受理しません。
法律と憲法は起草時の対象hashを固定し、並行する別案が先に成立した場合は、
古い全文で上書きせず不成立にします。

## 法令集

成立した憲法と法律の公開正本はDiscordではなく、Cloudflare Worker + D1 にあります
（`worker/README.md`）。botは差分だけをoutbox経由で押し込み、失敗しても
idempotency keyで二重掲載になりません。接続先が未設定なら押し込みを行わず、
統治機能はDiscord内だけで動きます。
