# 記憶 v2 (wiki の再設計)

v1 (`docs/memory-tree.md`) の「精度が足りず、内容が薄い」を直すための作り直し。
**精度を上げ、内容を薄くせず、むしろ詳細にする**。想起 (RAG) の単位と索引も、これに合わせて作り直す (Part B)。

## v1 の問題 (2026-10-29 の監査)

| | v1 |
|---|---|
| 規模 | ページ 4,693 / 出来事 12,030 / 読んだ発言 約 127 万 / 費用 $7.7 |
| 薄さ | ページの 58% は本文が空。topics の本文は平均 53 字。出来事は 発言 107 件に 1 件 |
| 精度 | 出来事 12 件の手検証で 正確 8 / 一部不正確 3 / 話者の取り違え 1。引用 (「」) の原文一致は 50% |
| 人物 | 同一人物が表示名ごとに別ページ、削除済み約 5 アカウントが 1 ページ、冗談・仮定・自己申告が事実に |
| 想起 | e5-small のスコアが 0.80〜0.91 に集まり「関係ある / 無い」を選り分けられない。ページ単位の hit@1/3/10 = 43/61/71%、断片 33/46/55% |

原因: AI に author_id を見せず表示名で人物を決める / 主張の根拠が出来事の番号止まり / ページを AI が何度も書き直す
(要約の要約) / 内容が根拠に合うかの検証が無い / 統合が逐次で並列にできない。

## 設計の柱

1. **事実は行から。** 話者・日時・引用の原文は、機械が行番号から決める。モデルは行番号を指すだけ。
2. **人物は author_id で決める。** 台本では発言者コード `A1…` で見せ、表示名は履歴として持つ。
3. **主張 (claim) が根拠と検索の単位。** 1 主張 = 1 命題 + 根拠の行 + 話の種類 (modality) + 時刻 + 属性。ページは主張から組み立てる。
4. **読む人と検証する人は別のモデル。** glm-5.3-flash が抽出し、deepseek-v4.1-flash-1017 が根拠に照らして判定する。
5. **削らずに降格する (非減少の原則)。** 検証は捨てる道具ではない。wrong だけがページに使われなくなり、weak は hedged で残り、
   冗談・仮定は出来事の中にだけ残る。文に入らなかった主張は機械が追記する。上限 (出来事 10 件・本文 3,000 字…) は置かない。
6. **想起は、主張を単位にした「ハイブリッド検索 + 再順位づけ + メモリパック」。**

すべての工程は冪等で、モデルの出力を入力のハッシュで保存する (止まっても続きから。検査を直したら保存した出力にも新しい検査をかける)。

## 構築 (Part A)

新しい DB `memory2.sqlite` (`MEMORY_DB_PATH`) に作る。v1 と同じ形の表 (nodes / episodes / episode_nodes / links …) は `store.ts` が作り、
その上に `v2_*` の作業用の表を足す (`src/memory/v2/schema.ts`)。完成したら投影 (`project.ts`) で v1 の形に写すので、
サイト同期・Worker・`/memory`・`memory` ツールは無改造で読める。

| 工程 | 担当 | 中身 |
|---|---|---|
| S0 準備 | 機械 (`prepare.ts`) | 20 分以上空く所で会話単位に切り、同じチャンネルの会話単位を約 2 万字ずつ詰めて**区間**にする。1 つの会話が長ければ、いちばん空いた所で割る。台本は `A1=たこ` の凡例 + コード、返信先 (`A2→A1`)、メンションはコードに直す。bot・削除済みは読まない |
| S1 抽出 | glm-5.3-flash (`extract.ts`) | 区間ごとに 1 回。出来事 (kind・title・summary・outcome・行番号・決め台詞の行) と主張 (about・text・type・modality・attrs・行番号)。発言 8 件以上の会話単位は出来事か skip が要る (抜けたら聞き直す)。出力が長さで切れたら区間を割って読み直す |
| S2 検証 | deepseek-v4.1-flash-1017 (`verify.ts`) | 区間の台本と出来事・主張を並べ、根拠の行に照らして ok / weak / wrong、話者の取り違え、話の種類 (冗談・仮定…) を判定。wrong はページに使わず、weak は hedged |
| S3 解決 | 機械 (`resolve.ts`) | 人物は author_id ごとに 1 つ (同名の別人は `~末尾4桁`、削除済みも別人)。もの は正規化した名前の一致だけで束ねる (意味での統合はしない) |
| S4 組み立て | deepseek (`compose.ts`) | 検証済みの主張から本文を書く (前の本文は渡さない)。各文に `[c12]` を付けさせ、保存時に `[e345]` (出来事) へ置換。根拠の無い文・入力に無い `[cN]` は捨て、文に入らなかった主張は機械が追記。主張が多い entity は種類ごとの子ページ (`people/たこ/立場と意見`) + 概要の親ページ。モデルの出力が使えなければ主張を並べただけの本文 |
| S5 筋書き | deepseek (`arcs.ts`) | 同じもの をめぐる出来事が 3 日以内に 4 件以上つながれば `events/` に時系列のページ |
| S6 根 | deepseek (`arcs.ts`) | 根のページ (bot が毎回読む) |
| 投影 | 機械 (`project.ts`) | v1 の形の表に写す。出来事の id は v2 のまま。wrong の出来事は写さない |
| 関門 | 機械 (`validate.ts`) | 構造・詳細さ (v1 以上)・精度 (評価セット) を数え、通らなければ切り替えない |

### 台本と区間 (S0)

```
[凡例] A1=たこ / A2=さば / A3=さば#0003
## #雑談 2025-03-14
### c1 (3発言)
1|14:02 A1: 今日のデプロイ落ちた / ログ見る
2|A2→A1: DB のロックっぽい
```

- 区間は範囲 (チャンネル + 最初と最後の発言) だけ持つ。同じ範囲からは同じ台本ができる。
- 区間が会話の途中から始まるときは、前の 6 行を「読むだけ」の文脈として付ける。
- 同名の別人は凡例で `#末尾4桁` を付けて見分ける。

### 「内容を薄くしない」保証

- 検証は降格であって削除ではない (wrong だけが使われない。記録は残る)。
- 件数の上限 (区間あたりの出来事・本文の長さ・主張の数) を置かない。
- 詳細さは**切り替えの関門**: 出来事 / 千発言、本文を持つページの割合、人物ページの本文の長さが v1 を下回れば切り替えない。
- 主張を持つ entity は必ず本文を持つ (組み立てが失敗しても、主張を並べた本文になる)。

`MEMORY_V2_CONCURRENCY` (16) / `MEMORY_V2_BUDGET_USD` (30) / `MEMORY_V2_SECTION_CHARS` (20000)。予算は台帳 (`ai_model_budgets`) で止まり、

## 測定 (2026-10-29)

### カナリア (36 区間、66 万字、$0.28)
- 出来事 1,186 / 主張 1,395。発言 1,000 件あたり約 50 件 (v1 は約 9.5 件)。結末つきの出来事 73%、数字・版・日付つきの主張 18%。
- 会話単位の網羅 100% (聞き直し後)。区間の割れ (出力が長さで切れる) は 1 件。
- 費用 (1 区間あたり): 抽出 $0.0024 / 検証 (deepseek、推論 medium) $0.0053 / 組み立て 主張 1,000 件あたり約 $0.03。
  全体 (2,332 区間): 抽出 約 $5.6 + 検証 約 $12 + 組み立て 約 $3。検証を切ると約 $9〜10。

### 精度 (Claude が主張 150 件を、根拠の行の前後つきで読んで付けた正解)
標本は検証の判定 × 話の種類で層化している (wrong・weak を多めに含む)。
- 検証が ok とした主張: 正解も ok 86〜91%、言い過ぎ (weak) 約 9%、完全な誤り 0〜3 件 / 79〜98 件。
- 正解が wrong の 19 件のうち、検証は 11〜13 件を wrong、5〜6 件を weak に降格し、ok のまま通したのは 0〜3 件。
- 使う主張 (wrong 以外) のうち主体が合っている割合 (話者の帰属) 97.8〜98.4%。
- 誤りの型: 別の人の発言の取り違え / 方向・主客の逆 / 仮定・提案を「した」と書く / 1 回の発言を「よく・口癖」と一般化 /
  根拠に無い固有名を補う。プロンプトに禁止を足した (抽出・検証)。
- 検証の設定を比べた: 推論 off は誤りの見逃しが増える (6/19)、glm を検証に使うのは deepseek より弱い (8/19 見逃し)。
  根拠の行の話者を併記すると、話者の誤判定 (正しい主張を wrong にする) が 6 → 1 に減った。
- 検証を外す選択もできる (`MEMORY_V2_VERIFY=off`)。標本から見積もると、検証なしで誤り 2〜5%・言い過ぎ 約 11% (v1 は不正確 25〜33%)。
  抽出結果は保存されるので、あとから検証だけ足せる。

### 想起 (v1 のデータ 12,764 断片、質問 1,800)
| | A (出来事の要約) hit@10 | B1 (短い質問) hit@10 | B2 (あいまい) hit@10 | 関係ない質問との分離 (AUC) |
|---|---|---|---|---|
| e5-small (現行) | 67.2 | 91.8 | 67.8 | 0.83 |
| e5-base | 66.5 | 93.2 | 69.3 | 0.76 |
| ruri-v3-130m | 64.3 | 96.0 | 81.0 | 0.94 |
- 語彙 (文字 3-gram BM25) と融合 (RRF) で e5-small の B2 は 67.8 → 78.0、ruri は 81.0 → 84.3。
- 判定モデル (jev) で上位 20 件を 1 回で再順位づけ: hit@1 72 → 87%、hit@3 81 → 91%。
  依頼そのものに「このコミュニティの具体的な話に触れているか」を 1 問聞く入口の門は、関係ある質問の 82% (閾値 0.2) を通し、関係ない質問を 100% 止めた。
