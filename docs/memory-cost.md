# Sakanaの記憶処理とAI費用

Atom MemoryはJSライブラリ。本番の履歴キュー、DeepSeek呼び出し、埋め込みworker、費用記録はSakanaが持つ。Atom本体にSakanaのAPIキー・料金表・Discord・常駐処理を入れない。

## 処理と支払い先

|処理|実行先|API料金|
|---|---|---|
|履歴・新着・編集の保存|既存SQLite|なし|
|意味単位への分解、まとまり・関係・説明の改訂|DeepSeek Writer|入力・出力tokensに応じる|
|Atom・関係・文脈・明示的な検討状態のベクトル|既存ローカルE5|なし。CPU・メモリは使う|
|索引と関係の検索|Atom MemoryとSQLite|なし|
|会話・警察・裁判・議会の推論|各機能の既存モデル|各機能の呼び出し分|

埋め込みはmain processの既存Python workerを共有する。Atomのworkerごとにモデルをロードしない。モデルの出力次元を実際に検査し、query/passageを区別する。初回履歴は差分索引を少量ずつ作り、新しく確定したWriterのAtomは優先して索引へ入れる。

## 2026-09-12に確認したDeepSeekの料金

[公式料金表](https://api-docs.deepseek.com/quick_start/pricing/)によるUSD／100万tokens。現在の標準名は `deepseek-flash`。旧 `deepseek-v4-flash` のリクエストも現在のFlashに振り替えられる。

|Flash|割安時間|ピーク時間|
|---|---:|---:|
|入力・キャッシュなし|$0.15|$0.30|
|入力・キャッシュあり|$0.003|$0.006|
|出力|$0.60|$1.20|

ピークは平日01:00–04:00、06:00–10:00 UTC。それ以外は割安時間。料金は変わり得るため、コードの料金表も見直す。

初回は本文だけでなく、指示・返信先・直前の文脈・必要な既存記憶・再試行の入力も課金対象になる。9月11日に観測した49発言／入力41,258・出力6,446tokensと、13発言／入力18,691・出力5,534tokensを、キャッシュ割引なし・現在の割安料金で104万件へ単純換算すると、約$213と約$490。旧モデルの少数バッチからの参考値で、全履歴の見積もりを確定する試料ではない。小さいバッチの固定費と、訂正に伴う再整理で大きく変わる。

毎月の費用は新着量・訂正量・会話や統治の呼び出し回数による。初回の履歴整理費用と分ける。通常会話や統治の費用を下のWriter専用集計に含めたとは扱わない。

## 実測と任意の上限

```sh
# どちらもAIを呼ばない。現在の保存済み実績を読む。
npm run memory:organize -- --status --guild SERVER_ID
npm run memory:organize -- --estimate --guild SERVER_ID
```

`--estimate` は直近100件の完了バッチの実tokensを未処理件数に換算する。試料がなければ見積もり不可を返す。再試行やデータ分布の差は別途考える。

`memory_writer_calls` はリクエストごとに使用量・その時点の料金・推定USDを記録する。AI出力が後段の検証で拒否されても、消費した呼び出しを集計から落とさない。通信中にプロセスが落ちてusageが不明なら、未確認の予約額として残す。推定料金はプロバイダーの確定請求額ではない。

`MEMORY_WRITER_DAILY_USD` を設定すると、UTCの日ごとにWriterのAPI予算を適用する。空欄は金額上限なし、`0` は有料Writerを停止。実績と未確認予約額に次のリクエストの保守的な予約額を加えて判定する。上限で止まっても原文・未処理キュー・AIの確定済み結果は保持し、翌日再開する。原文同期とローカル索引は続けられる。

予算はWriter専用で、裁判や通常会話をこの設定で止めない。既存の会話・統治の予算と権限判定は引き続き各機能が持つ。

## 今回の検証と本番

ライブラリとSakanaの変更はローカルで検査する。以前のProxmoxリリースが稼働していることと、今回のコード・索引・費用管理が本番に反映されたことは別である。今回の本番切替と実DeepSeekによる再試験は、接続先・認証と設定を確認してから行う。

## 長期間の履歴を段階的に整理する

Writerは同じチャンネルの未処理履歴を既定で最大7日・60件・60KBの範囲にまとめる。30分の固定区切りは廃止した。疎な会話は数日分を一度に読め、活発な会話は件数・バイト上限でさらに分かれる。`MEMORY_WRITER_BATCH_WINDOW_MS`、`MEMORY_WRITER_BATCH_MESSAGES`、`MEMORY_WRITER_BATCH_BYTES` で調整できる。期間は転送上の範囲であり、話題の分類やその期間全体の完了を意味しない。

AIは過去の整理を `memory_search` で調べ、同じ話題のAtomを再利用・改訂し、新しい情報と関係をまとめて最大40 Atomの編集計画にする。`MEMORY_WRITER_MAX_STEPS` は検索と最終出力を合わせて既定6回まで。1回で足りればそこで完了する。件数だけを増やすと出力予算や文脈の限界に当たり得るので、実際の利用量と整理品質を見て調整する。

Sakanaの進捗単位は処理済みのメッセージ世代で、モデル結果・Atom確定・索引・永続化のチェックポイントから再開する。失敗時に期間全体を読み直したり、確定済みのモデル呼び出しを繰り返したりしない。AtomのJSライブラリには長期ジョブや課金スケジューラーを持ち込まない。
