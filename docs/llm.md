# このサーバーの94万件だけで学習した言語モデル

`/model` で選べる `evex` の中身。DeepSeek の代わりではなく、**このサーバーのログだけを
世界として学習した 5.87M パラメータのモデル**で、道具も検索も使えず会話の続きを1発言書くだけ。

## まず測った

作る前に実データを測ったら、当初の見積りと桁が合わなかった。

```
archive.sqlite        941,263 件 / 15,701,106 文字 / 2,647 人 / 281 チャンネル
  人間                585,628 件 / 11,730,065 文字  (平均 20.0 文字)
  bot                 355,645 件 /  3,971,159 文字  (38%)
```

bot の 38% のうち **`mizuki-2.3-rakutenai-law` 単独で 301,109 件** = アーカイブ全体の 32%。
学習からは bot を全部外した。

tokenizer を通した実数:

```
train   6,495,896 トークン (53,650 会話)
val       189,256 トークン ( 1,286 会話 / 最後の14日)
合計    6,685,152 トークン
圧縮率  2.40 文字/トークン
```

**当初の見積り (1,860万〜9,300万トークン) は 20〜100 トークン/message を仮定していた。**
実測は 13 トークン/message で、下限すら割る。Chinchilla 最適 (20 トークン/パラメータ) は
**33万パラメータ**で、5.87M でも最適の 6%。汎化ではなく暗記寄りになるのは避けられない。
目的が「このコミュニティの文化を圧縮する」なので、それ自体は失敗ではない。

| | 当初の案 | 実測から引き直した |
|---|---|---|
| 総トークン | 1,860万〜9,300万 | **669万** |
| モデル | 15〜20M | **5.87M** |
| context | 1024 | **512** |
| vocab | 8192 | **4096** |

context を 512 にしたのは、`splitIntoChunks` が会話を 20 件 / 1200 字で切っているから。
1200 字 ÷ 2.40 = 500 トークンなので、**512 でちょうど会話 1 件が丸ごと入る**。
1024 は要らない上に attention が 4 倍。

## コーパスの作り方

会話の切り方は意味検索と同じ `splitIntoChunks` を import する (無言 15 分 / 20 件 / 1200 字)。
定義を2箇所に持つと必ずずれるので実装しない。

```
<|conv|><|s7|>責任という問題だけが残る<|s8|>ガッ<|s0|>逆にどれだけ綺麗にコードを書いても
ユーザーの問題で発生する可能性って言うのを捨てられにゃいから<|s0|>エラー処理は必要
<|s0|>rebaseマジで疲れた<|s0|>もうrebaseしません!<|s0|>mergeしか勝たん<|end|>
```

- 話者は**上位48人だけ固有トークン**で、人間の発言の 85.3% を被覆。残りは `<|other|>`
- `<|re|>` は返信 (`messages.reply_to`)
- URL / メンション / チャンネル / 時刻は潰す。**カスタム絵文字は名前を残す** (`:kusa:` は文化)
- **残すもの**: 絵文字・`草`・`www`・顔文字・伸ばし棒。文体そのものなので消さない
- 本文が空 (添付・スタンプ) は `<file>` にして turn は残す。会話の間が消えると流れが壊れる

正規化と直列化は `src/mimic/serialize.js` に置いて、学習データ (`build-corpus.mjs`) と
推論 (`respond.js`) の両方がそれを使う。**ここがずれると例外は出ず、モデルが
「学習中に一度も見ていない形」を受け取って静かに崩れるだけ。**

## 踏んだもの

どれも例外を出さずに黙って壊れる類だった。

**Node の `readline` は U+2028 も行終端として扱う。** `JSON.stringify` はこの文字を
素通しするので、それを含む本文 5 件で JSON レコードが割れた。`wc -l` では気づけない
(あちらは `\n` しか数えない)。`readline` をやめて `\n` だけで切り、正規化でも潰す。

**`add_dummy_prefix` が全行頭に `▁` を入れる。** 話者トークン単体が 2 トークンに割れ、
往復も戻らなくなる。チャットの1行は文の途中ではないので `false` にする。

**`remove_extra_whitespaces` の既定が true。** コードブロックのインデントが 1 スペースに
畳まれる。往復が戻らない 35/1000 行の原因はこれだった。

**`character_coverage=0.9995` が語彙を食い潰していた。** 3,037 文字を語彙に入れる必要があり、
4096 枠のうち**実マージが 410 個しか残らなかった** (= 日本語がほぼ文字単位)。
0.995 なら 1,492 文字で足りてマージが 2,285 枠に増える。捨てる 4,216 文字は
全体の 0.5% なのでバイト送りで足りる。

```
              圧縮率   出現100回未満の語彙
0.9995 →     2.00      1,898 / 4096
0.995  →     2.40        341 / 4096
```

**正規化の二重適用。** `normalize` は URL を潰してから改行を `<nl>` にする順序なので、
一度通した文をもう一度通すと `https://<nl>Current` の `<nl>Current` まで URL として飲まれる。
共有モジュールに切り出すリファクタで踏み、**前後でコーパスを byte 比較して1件だけ検出できた。**

## モデル

```
Decoder-only Transformer     5,868,800 パラメータ (埋め込み 18%)
layers 6 / d_model 256 / heads 4 / d_ff 704 / context 512
RoPE + RMSNorm + SwiGLU + weight tying
dropout 0.1 (残差のみ)
```

配線の確認として、乱数列を暗記させて loss が落ちることを見る (8.39 → 0.0119 / 200 step)。
最初これが落ちきらず焦ったが**原因は dropout** で、暗記テストは「配線が通っているか」を
見るものなので切るのが正しい (0.1 のままだと 400 step でも 0.62 止まり)。

## 学習を 3.9 倍速くした

素朴に書いたら 1,418 tok/s で 8 epoch に 10.2 時間かかる見込みだった。11.5 コア使って
いるのに遅いので実測で切り分けたら、**独立な原因が2つあって掛け算で効いていた**。

**1. アテンション内の dropout。** `dropout_p > 0` を渡すと
`scaled_dot_product_attention` は融合カーネルを使えず、`B×H×T×T` のアテンション行列を
実体化する math 経路に落ちる (24×4×512×512 で 1 層 100MB、6 層ぶんの往復でメモリ帯域を
食う。RSS が 4.5GB あったのはこれ)。正則化は残差側の dropout で足りるので 0 にした。

**2. スレッド数。** この機械は i5-12600K で、16 は「スレッド数」であって
**P コア 6 + E コア 4 の異種構成**。同期並列の行列積を全スレッドに広げると P コアが
E コアを待つので、素朴に 16 を渡すと逆に遅い。

```
attn_dropout=0.1 threads=16 → 1,418 tok/s (76.3 分/epoch)   ← 最初
attn_dropout=0.1 threads= 8 → 3,078 tok/s (35.2 分/epoch)
attn_dropout=0.0 threads=16 → 2,104 tok/s (51.5 分/epoch)
attn_dropout=0.0 threads=12 → 5,476 tok/s (19.8 分/epoch)   ← 採用
```

4 スレッド以上はほぼ横並びで、16 だけが外れ値。

bf16 は使えない。Alder Lake は AVX-512 が無効なので `avx512_bf16` も AMX も無く、
AVX2 の fp32 が上限。

学習はこの開発機で回す。**bot のサーバー (12GB / bot と Chrome が稼働中) では回さない。**
アーカイブは生の行として1回だけ持ってきて、以降サーバーには触っていない。

## Discord に載せる形

`/model` で **誰でも自分のぶんだけ**切り替えられる (`agent_engine` 表)。

```
/model                     いまの選択と Evex の起動状態
/model engine:DeepSeek…    検索・read・web・引用つきのエージェント
/model engine:Evex…        会話の続きを1発言だけ返す
```

**推論は bot と別プロセス。** CPU 推論をイベントループ上で回すと Discord の REST が
全部落ちる (チャンク生成で 28 秒固めたのと同じ形)。`127.0.0.1:8765` で待ち受ける常駐
プロセスに投げ、落ちていたら「起動していません」と返して bot 自体は止めない。
`browser` ツールは `urlguard` がループバックを塞いでいるので SSRF で到達する経路は無い。

**使用量は記録しない。** API を叩いていないので費用がゼロで、ドル換算の上限
(`agent_calls`) に混ぜると請求と乖離する。同時実行は 1 件に絞る。

**誰かに成り代わらせない。** 話者は `<|other|>` (上位48人に入らない 2,599 人ぶんの発言 =
このサーバーの平均的な声) で固定。94万件を何周もしている以上、特定の人の名前で書かせると
**「その人が言いそうなこと」ではなく「その人が実際に言ったこと」**を思い出して出しうる。

放っておくとモデルは `<|s3|>…<|s7|>…` と会話を続けるので、次の話者トークンか `<|end|>` で
切って1発言だけ返す。切らないと他の人の発言まで捏造した長文が流れる。

## 期待できること / できないこと

669万トークンという制約は埋めようがない。TinyStories が 10M 未満で通ったのは
データが 5 億トークンかつ意図的に単純化されていたからで、実チャットログはノイズが遥かに多い。

**期待できる**: 口調・ネットスラング・コミュニティ内の用語・人物名・よくある会話の型

**期待しない**: 一般常識・推論・数学・プログラミング・長い整合性・知らない質問への応答

**逐語で吐き出す**。誰かの過去の発言が文脈なしに出てくることがある。許可サーバー内で
完結させる前提で、返答には毎回「事実の保証はありません」を付ける。
