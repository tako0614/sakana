# 記憶の本

公開チャンネルの過去ログを区切りごとに AI へ渡し、サーバーについての記憶をファイルシステムのような木に整理する。会話 agent は根だけを system に常駐させ、会話に出た名前から関係するページと出来事を思い出し、足りなければ `memory` ツールでたどる。Atom (1発言ごとの投影・埋め込み・Writer・Dream) は廃止した。

## なぜ作り直したか

2026-10 の本番で測った値。

| | 値 |
|---|---|
| 発言の長さ | 平均 15.9 字、半分が 5 字以下、38% が bot |
| 旧 Writer の消費 | 1 発言あたり入力 2,020 / 出力 508 トークン (1 回 3 発言、460 回の実績) |
| 旧 Atom DB | 23.6 GB (整理済みの知識は 2,165 件) |
| 旧 Writer の待ち | 約 106 万件、再試行中 4.3 万件、DeepSeek の残高切れ (HTTP 402) で停止 |

中身の 100 倍以上を、JSON の封筒・ツール定義・想起・エージェントの往復に払っていた。原文は小さい (人間の発言は全期間でおよそ 1,000 万字) ので、短い台本にして一度ずつ読めば足りる。

## 2つの層

人の記憶と同じく、出来事の記憶と知識を分ける。

- **出来事 (episode)** — いつ・誰が・何を・どうなったか、の 1〜4 文の要約。種類は問わない: 決定や事件だけでなく、レスバ・口論 (双方の言い分と結末)、ネタ・ミーム、名言・迷言、炎上、人間関係の変化、予言とその結末も残す。自由な種類名 (`kind`: レスバ / ネタ / 事件 / 決定 / 近況 …) を持ち、それでも探せる。根拠の発言 (message_id) と、決め台詞として残す発言 (`highlights`、モデルには行番号で指させ、原文はアーカイブの発言をそのまま使う) を持つ。時刻は根拠の発言から取る (モデルが書いた日付は使わない)。続き・原因・結果・蒸し返しになっている過去の出来事と結ぶ。
- **ページ (node)** — 人物・作っているもの・話題などの説明。出来事から分かった知識を統合して書き直す。ログの写しや日記にはせず、「何者か / 何をしているか / 今どうなっているか / 誰・何とどう関わるか」を現在形で書く。主張ごとに `[e12]` で出来事を引き、`[[people/さば]]` で他のページへリンクする。

```
(根)                サーバーの概要。system に常駐 (上限 2,600 字)
├─ people/          人物
│  └─ たこ          説明 [e12] … [[projects/sakana-bot]] … / 子ページ
├─ projects/        作っているもの
├─ topics/          話題・知見
├─ events/          大きな出来事のまとめ
├─ debates/         レスバ・議論・揉め事
├─ culture/         ネタ・ミーム・名言/迷言
├─ server/          ルール・チャンネル・用語
└─ others/          どれにも合わないもの (育ったら最上位に昇格)
```

ページには別名 (表記ゆれ・あだ名) を持たせる。人物のページには立場や意見を時期つきで残す (何について何派か。後でダブスタかどうか比べられるように)。最上位は people / projects / topics / events / debates (レスバ・議論) / culture (ネタ・名言) / server / others (受け皿) を種にする。書き手は最上位を必ずこの一覧から選び、どれにも合わなければ others に入れる (最上位を勝手に増やさない)。最上位の下は自由 (子・孫まで、名前も自由。深さは4まで)。最上位を増やす・消すのは管理者で、`/memory category add name:… from:others/…` で others に育ったまとまりを最上位に昇格でき (ページ・出来事のつながり・本文の [[リンク]] ごと移る)、`remove` で消すと中身は others の下へ移る。最上位は20個まで。

つながりは3種類: 出来事に関わったページ (`episode_nodes`)、同じ出来事に関わったページどうし・本文の `[[リンク]]` (`links`)、出来事の前後 (`episode_links`)。これで「ページ → 関わった出来事 → 元の発言」「2つのページが両方関わった出来事」「出来事の前と後」をたどれる。

## 書き方

`scripts/memory-tree.mjs run` が次の3種類の呼び出しだけで育てる。どれも1回で完結し、tool の往復はしない (無料枠は回数で数える)。

1. **区切り** — 公開チャンネルの続きを、行番号つきの短い台本 (`12|14:02 たこ: 本文`) にして約4万字ずつ渡す。返ってくるのは出来事 (根拠の行番号・関わったページ・前の出来事) と知識 (どのページの説明に足すか、どの出来事が根拠か)。小さいチャンネルは1回に詰め合わせる。
2. **統合** — 知識が 1,200 字溜まったページを数件まとめて書き直す。本文のまだ無い新しいページは、空いた統合の枠で10件ずつ最初の本文を書く (読み終えるまで「まとめ中」のまま待たせない)。統合待ちが 6,000 字を超えたページ (人のページは数万字になる) は、書き直す前に統合待ちを番号で子ページへ仕分ける (`people/あかり/Linux・環境` など。書き直さないので1行も落ちず、仕分けた先で普通に統合する)。人のページの子は話題の切り口なので、想起の名前の照合には入れない。読み終えたら残りも書き直す。本文が 3,000 字を超えるときは、まとまりごとに子ページへ分け、本文には概要と子へのリンクを残す。
3. **根** — 区切り30回ごとと実行の終わりに、最上位と重いページから概要を書き直す。

書く側の工夫:

- **書く前に既知を渡す。** 区切りに出てくる名前・別名から既知のページを引き、説明・本文の冒頭・最近の出来事 (e 番号つき)・つながりを渡す。知っていることを繰り返さず、変わったことは変化として書き、続きの出来事は前の出来事と結ばせる。区切りの呼び出しにページの本文全体は渡さないので、木が育っても1回の入力は増えない。
- **形を決めて書かせる。** 出来事は「誰が・何を・なぜ・どうなったか」、知識は「ページの説明に足す文」。「〜と言った」の形にしない。意見・冗談・推測は事実と分ける。変化は上書きせず「以前は〜、YYYY-MM から〜」。
- **機械的に検査して捨てる。** 実在しない行番号しか持たない出来事、根拠の出来事が無い知識、ログを10字以上の単位でほぼそのまま写した知識 (8割以上一致) は捨てて、`run` の結果に数を出す (`dropped`)。統合では、本文が長すぎる・中身の7割以上を落とした・`[e]` の根拠を全部落とした書き直しを受け取らない。3回失敗したページは、知識を落とさないよう統合待ちを本文の末尾へそのまま移す。

台本は bot・削除済み・空の発言を除き、同じ人が3分以内に続けた発言を1行にまとめ、時刻は10分以上空いたときだけ書く。表示名は時期で変わるので、その人の最新の名前に揃える。1行にまとめた発言はすべて、その行番号から元の message_id に戻せる。

区切りの結果と読んだ位置 (cursor) は同じトランザクションで保存する。止まっても続きから読む。新着は 6,000 字貯まるか、最後の発言から12時間経つまで待つので、呼び出し回数は新着の件数に比例しない。読めない出力が3回続いた区切りは `failed` として記録して先へ進み、`--retry-failed` (定期実行に付けてある) で読み直す。読み直しも1区切り3回までで、それでも駄目なものは `failed` のまま `/memory status` に数が出る。

## 思い出す・たどる

木があるサーバーでは、会話 agent に次を渡す。

- **根** — system の末尾。概要と、最上位ごとの重いページの名前 (上限 2,600 字。毎回同じ文面なのでキャッシュが効く)。
- **思い出したこと** — 依頼と返信先 (強い手がかり)・直近の会話 (弱い手がかり) に出てくるページ名・別名と、依頼の言葉の全文検索から、ページを最大3件と、その重要な出来事、2つ以上思い出したときはその両方が関わった出来事。何も当たらなければ何も足さない (上限 1,800 字)。埋め込みは使わない。
- **`memory` ツール** — `path` でページ (説明・子・つながり・関わった出来事)、`path` と `with` で2つが両方関わった出来事、`query` でページと出来事の検索、`episode` で出来事・前後の出来事・根拠の発言。根拠の発言には会話と同じ引用番号 `[3]` を振るので、そのまま根拠として示せる。根拠の発言は開くときにもう一度、いま公開のチャンネルか・消されていないかを確かめる。

## モデルと無料枠

`MEMORY_TREE_MODELS` を前から試す (既定は `z-ai/glm-5.3-flash`、次に `inclusionai/ling-3.0-flash`)。2026-10-15 に本番の同じ区切り (約2.3万トークン) を読ませて比べた結果:

|モデル|1回の費用|時間|結果|
|---|---|---|---|
|glm-5.3-flash|$0.0033|63秒|出来事18・知識17。日付・固有名が正確で、別名 (えだまめ = EdamAmex) も見抜いた|
|ling-3.0-flash|$0.0015|42秒|出来事26・知識18。細かいがページの振り分けが雑|
|qwen3.7-flash|$0.0016|74秒|出来事5。粗い|
|deepseek-v4-flash / gpt-oss-120b|―|―|思考で出力枠を使い切って失敗|
|nemotron-3-ultra:free|0|264秒|出来事42。良いが遅い|
|gemma-4:free|―|―|混雑で 429|

Evex の人間の発言は約129万件 (2,267万字) で、そのうち公開チャンネルの約64万件を読む。glm-5.3-flash で区切り約650回・統合を含めて約900回、数ドル。思考は `MEMORY_TREE_REASONING=low` (既定) で抑え、出力は JSON 専用モードにする (使わないと約20回に1回 JSON が壊れた)。

呼び出しは `MEMORY_TREE_CONCURRENCY` (既定8) 本まで同時に走らせる作業プールで、1本終わるたびに次を投げる。区切りはチャンネルが、統合はページが重ならないように組み (統合は幅の半分まで、1回4ページ・1.5万字)、結果はそれぞれのトランザクションで1つずつ反映する。統合待ちは末尾に足すだけなので、同じページに区切りと統合が触っても食い違わない。同じ波の区切りは互いの結果を「既知のページ」として見られないが、次の波からは見える。

:free の枠は1分20回・1日50回で、OpenRouter でクレジットを累計10ドル以上買っていれば1日1000回。待てば済む 429 は待ち、10分より先まで待たされる 429 は日の上限とみなして止まる。次の timer 起動で続きから読む。

有料モデルを混ぜるときは `MEMORY_TREE_BUDGET_USD` に累計の上限を置く。0 のままだと `:free` 以外の route を拒否する。

OpenRouter の stealth モデル (`stealth/space-bunny-alpha` のような匿名のテスト中モデル) は `:free` が付かないが 0 円で、無料枠の回数制限とは別に使える。期間が終わると消えるか有料の別名になるので、`MEMORY_TREE_MODELS=stealth/<名前>,google/gemma-4-31b-it:free,...` のように先頭に置き、`MEMORY_TREE_BUDGET_USD=1` を安全装置として置く。消えた route は価格が取れずに次のモデルへ落ちる。stealth は入力を記録・学習に使う前提のものが多い。費用は既存の `ai_model_calls` 台帳に `memory-segment` / `memory-integrate` / `memory-root` として残る。

無料の endpoint には入力を記録・学習に使うものがある。公開チャンネルのログしか送らないが、送ってよいかは OpenRouter の Privacy 設定と各モデルのページで確認してから回す。

## 読む範囲

記憶に入るのは、bot が控えた「@everyone と bot の両方が読めるチャンネル」と、その下の非公開でないスレッド、それに管理者が `/memory include` で入れたチャンネル (ロールが要るチャンネルなど) とその下の非公開でないスレッド。2026-10 の Evex では @everyone から見えないチャンネルに人間の発言の半分 (#generax 47万件・#taxt 12万件・#nsfw 5万件など) があり、#generax・#taxt・#nsfw を入れた。運営用 (#internal・#moderator-room) は入れていない。追加したチャンネルの内容は、そのチャンネルを見られない人にも思い出される。`/memory exclude` で外すと以後は読まないが、読んだ分の記憶は残る。builder は Discord につながらないので、bot が起動時と30分ごとに `public_channels` へ控えを書き、builder はそこに無いチャンネルを読まない。控えが無ければ builder は何もしない。

nsfw のチャンネルも公開なら読む。提供元が拒否した区切りは `failed` として記録され、`--retry-failed` で別のモデルに読み直させられる。

記憶は公開範囲だけから作るので、そのサーバーの誰に見せてもよい。後から非公開になったチャンネル・削除された発言から書いた出来事とページの文は残る (根拠の発言は開けなくなる)。消したいときは `reset` して作り直す (原文のアーカイブには触らない)。

## 操作

Discord からは `/memory` で見る・止める。返事は本人にだけ見える。

|サブコマンド|内容|使える人|
|---|---|---|
|`status`|読んだ件数と割合・見込み・失敗・ページと出来事の数・費用・実行中か・追加したチャンネル|管理者|
|`pause` / `resume`|読み込みの一時停止と再開 (区切りの境目で止まり、再開は builder をすぐ起こす)|管理者|
|`include` / `exclude`|@everyone が見られないチャンネルを入れる・外す|管理者|
|`category list` / `add` / `remove`|最上位の一覧・追加 (`from` で昇格)・削除 (中身は others へ)|管理者|
|`explore`|記憶の本をメニューでたどって読む。ページはパンくず・本文 (リンクは太字の名前)・子ページ (20件ずつ)・つながり・最近の出来事。出来事は種類・日付・チャンネル・決め台詞の引用・根拠の発言へのリンク・前後の出来事。🕒 年表 (古い順に10件ずつ)、🔍 探す (入力欄)。📢 みんなに見せる で今の画面をチャンネルに出し、出したメッセージは誰が押しても全員の画面が変わる (一緒にたどる)。🔎 自分で開く で押した人にだけ同じ画面を開く。NSFW チャンネルの出来事は NSFW のチャンネルでだけ共有できる|誰でも|
|`show` / `search` / `episode`|ページ・検索・出来事と根拠の発言 (リンク付き)|誰でも|

builder を直接操作するとき:

```sh
node scripts/memory-tree.mjs status   --guild ID   # 進み具合。AI を呼ばない
node scripts/memory-tree.mjs try      --guild ID [--model M]   # 次の区切りを1回だけ投げて出来事・知識を表示 (保存しない)
node scripts/memory-tree.mjs run      --guild ID [--max-calls N] [--max-minutes M] [--retry-failed]
node scripts/memory-tree.mjs show     --guild ID --path people/たこ [--with people/さば]
node scripts/memory-tree.mjs episode  --guild ID --id e12
node scripts/memory-tree.mjs search   --guild ID --query 統治
node scripts/memory-tree.mjs recall   --guild ID --text "さばって何作ってたっけ"   # 会話でこう聞かれたら何を思い出すか
node scripts/memory-tree.mjs root     --guild ID   # system に入る文面
node scripts/memory-tree.mjs estimate --guild ID   # 未読の量と呼び出し回数の目安 (アーカイブを走査するので重い)
node scripts/memory-tree.mjs export   --guild ID --out DIR   # ページを Markdown に、出来事を episodes.md に
node scripts/memory-tree.mjs reset    --guild ID --yes
node scripts/memory-tree.mjs reopen-empty --guild ID [--yes]   # 出来事が1つも無いまま「完了」になった長い区切りを読み直しに回す
node scripts/memory-tree.mjs settle   --guild ID   # 結果の返らなかった呼び出しの予約を OpenRouter の実額で精算 (run も最初にやる)
```

予算の予約: 呼び出す前に「最も高い provider で入力も出力も上限まで使った」額を予約し、返ってきた実額で置き換える。プロセスごと止めたり応答が途中で切れたりすると予約のまま残り、1件あたり実費の約10倍で上限を埋める (2026-10-15 は 107 件・$4.40 が残り、実費は $0.46 だった)。run は最初に OpenRouter に今月の請求額を聞き、台帳で確定した額との差を1時間より古い未確定の呼び出しに按分して精算する。予約のせいで止まっていた予算はそれで再開する。

provider の当たり外れ: OpenRouter は同じモデルを複数の provider に回す。2026-10-15 には glm-5.3-flash の一部の provider が、3万トークン読ませても空の JSON だけを返したり、出力の上限まで暴走したりした。builder は長い区切り (`MEMORY_TREE_EMPTY_CHARS`、既定 4000 字) で出来事も知識も空なら読めていないとみなし、その provider と途中で切れた provider を3時間外して送り直す。最初から外したい provider は `MEMORY_TREE_IGNORE_PROVIDERS` に書く。OpenRouter の「安い順」は主に入力の単価で並べるので、入力3万・出力4千トークンほどの区切りでは出力の高い provider (Reka は出力 $1.6/M、1回 $0.0094) が選ばれやすい。`MEMORY_TREE_MAX_PRICE=0.1,0.3` (入力,出力) で上限を付けると、StreamLake (1回 $0.0017) などに寄る。

`--guild` を省くと `MEMORY_TREE_GUILD` を使う。builder は同時に1つだけ動く (ロック)。本番では `deploy/sakana-memory.service` を `deploy/sakana-memory.timer` で起動する。溜まっている分は読み切るまで続け、読み終えたら1時間おきに新着を読む。モデルを決める前に `try --model` で同じ区切りを候補ごとに読ませ、出来事の切り方・知識の書き方・捨てられた数を比べる。
