# vex: 会話に入るかどうかを判定モデルで決める

発言に「vex」が出たときの扱いを `VEX_CALL` で選ぶ: `1` = メンションと同じに確定で答える / `judge` = 判定モデルに文脈で決めさせる / `0` = 何もしない (既定)。
呼ばれていない会話でも、役に立つときだけ自分から入る (自発参加、`VEX_AMBIENT`)。どちらも環境変数で、既定はオフ。`.env.example` の「vex」の節にある。
**本番の現状 (2026-10-20): `VEX_CALL=judge` (名前が出た発言を判定モデルに回す)、自発参加は #雑談だけオン**。切り替えは `/vex` コマンド (下)。
Discord のメンションと bot への返信は、いつでも確定で答える。

## `/vex` コマンドで切り替える (2026-10-20)

環境変数を変えて再起動しなくても、管理者 (「サーバー管理」権限か `ARCHIVE_ADMIN_USERS`) が Discord から切り替えられる。値は DB (`vex_settings`) に残り、
環境変数より優先する。bot 全体の設定で、サーバーごとではない。

| コマンド | 内容 |
|---|---|
| `/vex status` | いまの状態と、直近 24 時間の判定 (送った・(skip) で黙った・閾値未満・失敗の数と費用) |
| `/vex call mode:<off\|mention\|judge>` | 「vex」と名前が出た発言の扱い。off=何もしない / mention=確定で答える / judge=判定モデルが文脈で決める |
| `/vex ambient enabled:<true\|false>` | 呼ばれていない会話への自発参加のオン / オフ |
| `/vex channel action:<add\|remove> [channel]` | 自発参加してよいチャンネルを足す / 外す (省略するとこのチャンネル) |
| `/vex set key value` | `threshold` (0.05〜0.99)・`quiet_seconds` (3〜600)・`cooldown_minutes` (0〜1440)・`max_per_hour` (0〜60 の整数) |
| `/vex reset` | コマンドで変えた値をすべて捨てて、環境変数の値に戻す |

反映はすぐ (再起動なし)。止めたいときは `/vex ambient enabled:false` と `/vex call mode:off`。

## 動き

```
人の発言 ─ メンション/bot への返信 ──────────────→ agent (確定。これまでどおり)
        ├ 「vex」が出ている ─ VEX_CALL=1 ─→ agent (確定)
        │                  └ VEX_CALL=judge ─ 2 秒待つ ─ 判定モデル (閾値 0.45) ─→ 通れば agent (呼ばれた依頼として)
        └ それ以外 → チャンネルごとのタイマーを張り直す
                     │ VEX_QUIET_MS (90 秒) 静かだった
                     ▼
       門 (許可チャンネル・話せる・冷却・1時間の上限・判定費用の1日の上限)
                     ▼
       判定モデル → 「入る」の確率 p ≥ VEX_THRESHOLD (0.6)
                     ▼
       もう一度、最後の発言が自分の見ていたものか確かめる
                     ▼
       agent が「呼ばれていない。役に立つ一言だけ」の前置きで走る
                     ▼
       返す価値が無ければ (skip) → 送らない / 送る直前にも会話が進んでいないか確かめる
```

- 名前 (`VEX_CALL`): 発言に `vex` が英字の単語として含まれる場合 (`evex`・`vexx`・`vex2`、コード・URL・引用行・メンションの中は数えない)、
  `1` ならメンションと同じに確定で答える (相槌でも答える)。以下は `judge` のとき: 判定モデルに回し、確定では答えない。
  「vexにするか」のように名前を話題にしただけの発言は、判定で落ちることがある。
  どのチャンネルでも動き、続く発言や bot の発言では捨てない。冷却と 1 時間の上限は掛けない (呼ばれて続けて話すのを止めない)。
  判定費用の上限は掛ける。通ったら普通の依頼と同じに答える (呼んだ人の枠で数え、失敗も伝え、返信で通知する)。
  閾値は名前用の `VEX_NAME_THRESHOLD` (0.45)。名前は呼ばれている強い手がかりなので、自発参加の閾値より低い。
- 自発参加 (`VEX_AMBIENT` + `VEX_CHANNELS`): 判定に回さない発言 = bot / webhook・6 文字未満・相槌だけ・返信 (特定の相手との会話)・
  他の人へのメンション・NSFW チャンネル。bot (自分を含む) の発言が来たらタイマーは捨てる (自分の発言で輪を作らない)。
- 自発参加の agent は、最後に発言した人の `/model` や上限を使わない (既定のエンジン、専用の利用者 ID `vex-ambient` で数える)。
  経過表示は出さず、上限・失敗・(skip) は黙って終える。返信の ping は付けない。
- 判定が全部失敗したら入らない (名前呼びは判定を使わないので影響しない)。モデルは並べておき、429/5xx/時間切れで次へ回す。
  一度失敗したモデルは 60 秒飛ばす。
- 台帳 `vex_decisions` (メイン DB): 判定ごとに時刻・チャンネル・発言・モデル・p・費用・遅さ・どうしたか。
  `action`: joined (入ると決めた。冷却と上限はこれを数える) / below (閾値未満) / skipped (門で止めた。note に cooldown・hourly_cap・daily_budget・cannot_speak) /
  error / moved_on (会話が進んだ。note に before_decision・after_decision・before_send) / sent / passed ((skip))。

```sql
-- 閾値を決め直すための材料: p の分布と、入った結果
SELECT ROUND(p, 1) AS p, action, COUNT(*) FROM vex_decisions WHERE p IS NOT NULL GROUP BY 1, 2 ORDER BY 1;
```

## 判定モデル (Decisions API)

文章を作らず、`state` (会話) と型つきの質問を渡すと、はい/いいえの確率を 1 回で返す。
OpenRouter の `POST /api/alpha/decisions`:

```json
{ "model": "perplexity/pplx-decider-flash-v1.2",
  "state": { "conversation": "alice: ...\nbob: ..." },
  "questions": { "join": { "type": "noul", "instructions": "...", "criteria": { "true": "...", "false": "..." } } } }
```

返りは `answers.join.noul` (「はい」の確率) と `usage` (`input_tokens`・`cost`)。出力トークンは無料。質問の基準は `instructions` ではなく
`criteria` (はい/いいえの説明) に書く形がいちばん良かった (`src/vex/questions.ts`)。基準は `about` (呼ばれている・vex/bot/AI が話題・
答えのない質問・事実や技術の間違い → はい / 個人的なやりとり・独り言・すでに答えが付いた・直前に話した → いいえ)。

| モデル | 入力 100 万トークン | 手書き 30 件の AUC |
|---|---|---|
| perplexity/pplx-decider-flash-v1.2 (既定) | $0.01 | 1.0 |
| typesafe/jev-1.14 | $0.042 | 1.0 |
| inception/mercury-decide:free | $0 | 約 0.97 |
| respan/span-02 | $0.01 | 約 0.97 |
| liquid/d1 | $0.02 | 約 0.97 |

`solar-decide-flash` は 0.45 で除外。往復 0.4〜0.6 秒、429 はときどき出る。

### 費用

1 回 (6 件の会話、約 300 トークン) で約 $0.000003。実測では 45 チャンネル・1日 576 発言を全部判定しても月 $0.4 前後
(文脈 20 件で約 $0.6、100 件で約 $1.6)。400 場面の評価は $0.0012。VEX_DAILY_USD (既定 $0.05/日) で止まる。
入って答える agent のぶんは別 (`user_daily_usd` の枠に `vex-ambient` として数える)。

### 精度 (実際の会話)

公開チャンネルの 400 場面 (直接呼ばれた / 暗黙に質問があった / 静かだった / 普通に続いた) を弱ラベルにして、
pplx-decider-flash-v1.2、state は直近 6 件:

- AUC 0.843。暗黙の「入る」と「会話が続いた」だけで見ると 0.894
- 呼ばれた場面を除いた自発参加の場面だけだと AUC 0.769。閾値ごとの割合 (その場面のうち入る率 / 適合率 / 再現率):

| 閾値 | 入る率 | 適合率 | 再現率 |
|---|---|---|---|
| 0.4 | 29% | 0.58 | 0.51 |
| 0.5 | 11% | 0.67 | - |
| 0.6 | 5% | 0.81 | 0.13 |
| 0.7 | 1.75% (7 件) | 1.0 | - |

弱ラベルには雑音が多い (最後の発言が `@vex ...` なのに「会話が続いた」など) ので、実際の精度はこれより良い方向にぶれる。
閾値 0.6 は「ほとんど外さないが、控えめ」。本番では台帳を見て調整する。

ローカルの d1-3B Q4_K_M (CPU) は AUC 0.73〜0.75 で、暗黙と会話の区別がほぼつかなかった。CPU は 1 リクエスト 1〜3.4 秒。使わない。

### 基準をゆるめても「雑談に混ざる」は判定できない

質問の基準 (`criteria`) は「答えのない質問・頼みごと・事実の誤り・呼ばれている」のときに「はい」とする形で、雑談は「いいえ」。
これを「補足・ツッコミ・共感・面白い一言を足せるなら『はい』」(`scripts/vex/questions.mjs` の `chime`) にゆるめて、同じ 400 場面で測った。

| 場面 | いまの基準 p の中央値 / 0.6 以上 | ゆるめた基準 p の中央値 / 0.6 以上 |
|---|---|---|
| 呼ばれた (direct) | 0.78 / 71% | 0.70 / 68% |
| 答えのない質問 (implicit) | 0.41 / 13% | 0.71 / 91% |
| 静かだった (quiet) | 0.36 / 3% | 0.72 / 97% |
| 普通に続いた (active) | 0.22 / 3% | 0.71 / 89% |

ゆるめると、どの場面も p が 0.7 前後に張り付いて区別がつかなくなる (雑談の 97% が閾値を超える)。判定モデルは「何かを足せるか」には
常に「はい」と答えるので、「混ざると場が良くなるか」の見分けには使えない。**雑談に混ざる**ことは、判定の閾値ではなく、
入る回数の上限 (冷却・1時間あたり) と、agent 自身の `(skip)` (言うことが無ければ黙る) で絞るほうが筋がいい。
いまの基準は「困っている人・答えのない質問・呼ばれている」を拾うために調整してある。

### 質問だけの基準 (api) だと雑談の流れに入れなかった → about

最初の基準 (`api`: 質問・頼みごと・事実の誤り・呼ばれている) は、実際の #雑談 で「たまにバグるよな」「AIも認める無能、あるしゅくはい」
のような**自分が話題になっている**会話に p 0.25〜0.4 しか付けず、閾値 0.5 では一度も入らなかった。直近 20 時間の #雑談 (522 発言) に当てると、
`about` (vex・bot・AI の話題を「はい」に足した版) は同じ発言に 0.7 前後を付ける:

| 発言 | api | about |
|---|---|---|
| 今開発しててcladeが再起動してる説ある | 0.43 | 0.73 |
| jevで自分に返信されてるか判定するってこと？ | 0.59 | 0.73 |
| AIも認める無能、あるしゅくはい | 0.39 | 0.70 |
| 最近流行りのJevもどきはだいたいQwen 3.8 27Bのftだったと思う | 0.56 | 0.68 |

400 場面の弱ラベルでは AUC 0.843 → 0.787 (弱ラベルは「呼ばれた/質問」だけが正解なので、話題に反応させると下がる)。
閾値 0.55 での入る率は、静かだった雑談 5% → 20%、普通に続いた雑談 3% → 9%。入る回数の上限 (15 分・1 時間 3 回) と agent の `(skip)` で絞る。
`scripts/vex/replay.mjs` で、実際のチャンネルの直近の発言に基準を何通りか当てて比べられる。

### 質問を増やす・文脈を増やす案は効かなかった (2026-10-20)

「雑談に混ざる」判断を良くできないか、同じ 400 場面 (呼ばれた場面を除く 300 件) に、1 回の呼び出しで質問を 4 つ (`join`・個人的なやりとりか・
未解決の質問があるか・vex が話題か) 聞き、組み合わせを比べた (出力は無料なので、質問を足しても費用は同じ)。文脈も 6 件と 12 件で比べた。費用は計 $0.008。

| 組み合わせ (文脈 6 件) | 暗黙の質問 vs 雑談の AUC |
|---|---|
| `join` のみ (今) | **0.663** |
| join × (1 − 個人的) | 0.647 |
| 未解決の質問 × (1 − 個人的) | 0.618 |
| max(未解決, vex が話題) × (1 − 個人的) | 0.576 |

文脈 12 件にすると、どの組み合わせも下がった (`join` のみで 0.663 → 0.610)。判定モデルは「入るべきか」の見分けが弱く (どの形でも 0.55〜0.66)、
質問や文脈を足しても良くならない。**今の `join` 1 問・文脈 6 件が、試した中で最良。** 判定は安い一次ふるいと割り切り、
入ったあとに agent 自身が会話・記憶を読んで「(skip)」で絞る (前置き `AMBIENT_HINT` に、面白い・役に立つときだけ、内輪のやりとり・
答えが付いたものは黙る、迷ったら黙る、を書いた)。入る回数は冷却 (15 分)・1 時間の上限・判定費用の上限で抑える。

## 評価用スクリプト (`scripts/vex/`)

データは開発機の中だけ (リポジトリに入れない)。

- `export-situations.mjs`: 本番のアーカイブから、全員に見える公開チャンネルの場面を読み取りで書き出す
- `sanity.mjs`: 手書きの日本語 30 件
- `jev-api.mjs`: Decisions API で評価する。実際の発言を第三者に送るので、手書き以外は `--yes-send-real-messages 1` が要る
- `eval.mjs` / `latency.mjs`: ローカルの llama-server (`/v1/systemone`) 用
- `questions.mjs`: 評価に使った state と質問。`src/vex/questions.ts` と同じ形か `scripts/check-vex.mjs` が照合する

## 本番に入れる手順

1. `VEX_CALL=1` だけ入れる (判定モデルは使わない。費用は通常の agent と同じ)。
2. 自発参加は、テストチャンネル 1 つだけ `VEX_CHANNELS` に入れて `VEX_AMBIENT=1`。1 日 `vex_decisions` と実際の発言を読み、
   誤って入った率・入らなかった率を見てから広げる。
3. 止めるときは `VEX_AMBIENT=0` (再起動)。
